## 切换当天

1. 先部署测试并完成验收，继续保留原站。
2. 约定停止在旧站录入的时间。若旧站修订已不是 14，先在旧站以管理员身份重新导出完整 JSON 备份。
3. 对有新增记录的情况，使用最新备份初始化新的目标库，或在新站管理员的恢复入口导入最新备份；检查不会覆盖新站已经录入的工作。
4. 核对数据、账号和权限后，再切换员工入口或子域名。
5. 新站开始录入后，仅把新站作为业务写入入口，避免两份数据分别被修改。

## 备份与恢复

- 普通日常操作：使用工作台的 JSON 导出保存业务备份。
- 管理端离线导出：在 app/ 中配置目标库环境变量后执行：

```sh
npm run backup:export -- ../workbench-backup-YYYYMMDD.json
```

导出命令保留当前 state、revision、updatedAt 和 canUndo 信息，但不导出账号或历史快照。文件已存在时拒绝覆盖。账号单独保留初始恢复文件，并在增删账号后按数据库服务商的备份方式保留最新数据库。

- 恢复到新库：先 db:setup、再 accounts:restore、最后 backup:import。导入拒绝覆盖已有业务数据；若需要恢复现有业务库，先备份现状，再使用网站管理员恢复入口或创建新库。
- 代码回退不等于数据回退；Vercel 回滚部署后仍需确认数据库版本相容。
- 需要整库历史和账号的持续保护时，在自己的数据库账户配置对应备份方案并验证恢复。此交付未创建定时任务或购买备份服务。
